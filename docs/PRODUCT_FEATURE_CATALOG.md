## 1. 第一阶段定位

第一阶段只交付：**免费、完整、稳定的八字排盘工具**。同一个免费排盘页面同时承担普通用户排盘、直播展示、产品体验和引流，不单独开发直播课件页面。

- 用户在直播中看到的就是公开免费产品，所见即所得。
- 直播使用页面的大屏布局/浏览器全屏等展示方式，不另造一套课件、计算逻辑或数据状态。
- 免费排盘提供完整、可核对的本命资料和基础时间资料，不做故意残缺的试用版。
- 未来商业化按专题分析、AI 深度解读、合盘、报告及人工服务规划。
- 当前不接支付、会员、云模型，不开发合盘业务，不向 VPS2 或第三方发送出生资料，不重写引擎算法。
- 未来接口只做数据契约和边界预留，不代表现在已有这些服务。

## 2. 状态定义

| 状态 | 含义 |

| 已接入（待验收） | 现有功能盘点记录已调用接口，但真实浏览器/命例验收未完成 |

## 4. 当前最重要的差距

### 本命资料完整度
现有页面已接入四柱、藏干十神、纳音、五行、扶抑、十二长生、关系、大运、流年和神煞第一轮功能。下一步应优先补齐日柱剖面、地支剖面、十神柱位资料、空亡等已有引擎支持的内容。

### 时间关系联动
大运和流年不能只是独立卡片。应逐步形成“本命 × 大运”“本命 × 流年”“大运 × 流年”关系视图；节气和立春边界必须按引擎口径处理。

### 关系表达
两两关系只是基础。应区分单项命中、完整组合、合化条件和解释层。关系命中不等于合化成功，更不自动等于吉凶。

### 解释透明度
每项信息标明是引擎直接输出、按字段整理、前端规则归纳还是人工解释。五行数量、扶抑评分、神煞、十神不能互相替代。

### 直播与日常使用统一
不单独维护直播课件。页面在日常状态下服务普通用户，在直播时通过大屏展示方式服务讲解。直播时使用的排盘结果、模块和交互必须与公开产品一致，避免两套页面长期维护和结果分叉。

## 6. 引擎与页面统一约束

1. 逐步收敛为一次排盘产生一份标准化命盘快照，供所有本命模块共同读取。当前 lastBirth、lastChart、lastLuck、lastFavorable 是现有状态；大运和扶抑接口内部会重复排盘，后续可优化，但需先保证选项和输出兼容。
2. 记录出生资料、未知时辰、时区、经度、真太阳时、夏令时、换日口径、大运 method/frame、引擎版本和快照 schema 版本。
3. 十神、十二长生、干支关系、神煞统一使用引擎接口；页面负责组织和可视化，不另造互相冲突的算法。
4. 未知时辰必须贯穿五行统计、关系、神煞、大运和未来报告。任何模块不得自行补时柱。
5. 日常与直播共用同一页面、同一数据源和同一功能实现，不维护独立课件分支。

## 7. 第一阶段验收标准

### 计算正确性
- [ ] 常规命例及至少 3 个不同日干命例与独立可信历书核对。
- [ ] 立春、节气交界前后核对年柱/月柱切换。
- [ ] UTC+8、UTC+9 分别核对；未支持的海外历史夏令时必须明确说明。
- [ ] 中国历史夏令时开始/结束附近独立核验。
- [ ] 未知时辰不生成时柱，不将虚构时柱计入统计和神煞。
- [ ] 至少两种大运顺逆方向核对起运与大运干支。
- [ ] 五行统计、十二长生、十神、纳音、关系、神煞和空亡分别核对。

### 功能与体验
- [ ] 输入、四柱、藏干、十神、纳音、五行、扶抑、长生、关系、神煞、大运、流年和详情均可用。
- [ ] 从资料可定位到来源柱位；关系可定位参与干支；大运流年可回到本命。
- [ ] 桌面、手机无控制台错误；360px 无横向溢出。
- [ ] 同一页面在常规浏览和直播大屏场景下均可读、可操作；无需第二套课件页面。
- [ ] 模块切换不重复输入、不产生不同口径命盘。
- [ ] Network 无第三方排盘 API 请求。

### 隐私边界
- [ ] 免费排盘本地浏览器计算，不强制登录、不强制上传出生资料。
- [ ] 未来向 AI/人工服务发送出生资料前，必须明确授权用途、范围和保存期限。
- [ ] 第一阶段不依赖 VPS2 或云模型。

## 8. 商业化预留，不在本阶段启用

| 未来层级 | 能力 | 本阶段预留 |
|---|---|---|
| L0 免费 | 完整排盘、基础大运流年、同页直播展示 | 本阶段实际交付 |
| L1 专题 | 事业、财务、关系、阶段主题分析 | 命盘快照与专题输入/输出契约 |
| L2 AI | 用户提问、深度报告、追问 | Analysis API、异步任务、模型适配、报告版本字段 |
| L3 人工 | 人工复核、咨询、定制 | 服务工单和授权数据导出边界 |
| L4 合盘 | 伴侣、亲子、合作关系 | 多份命盘快照与关系结果契约 |

底线：免费核心计算不依赖付费系统；AI 消费已确认的命盘快照，不自行排盘；模型密钥只在服务端；订单权益由服务端校验；报告记录引擎/规则/提示词/模型版本；出生资料默认留在本地。客户数据存储位置和 VPS1/VPS2 职责在商业化实施前另行评审。
