## 1. 测试方法与边界

本轮从仓库读取 `vendor/lunar.js`、`vendor/bazi-engine.web.js` 和 `assets/app.js)，在隔离 JavaScript 运行环境中加载真实引擎，依次调用：

1. `computeBazi`：核对实际四柱与日主。
2. `computeFavorableElement`：读取 R20 简化扶抑结果及其 favorable/unfavorable 五行集合。
3. `computeLuckPillars`：按固定日期 `2026-11-03` 生成十步大运。
4. 执行前端当前 `getBasicLuckTrend` 逻辑，对每一步大运逐项生成标签。

所有测试输入均为人工构造的程序回归数据，不代表真实客户命盘，不是古籍命例，也不作为命理准确性的证明。性别只用于生成大运顺逆；统一采用 UTC+8、无经度、sect=1。未知时辰案例不填写小时。

本测试验证的是：前端标签是否忠实执行当前简化模型、不同状态是否正确兜底、十步大运是否均可处理。它不验证传统命理理论的完整正确性，也不替代桌面/手机真实浏览器测试或独立历书核验。

## 4. 本轮发现与修正

代码审阅发现，旧版解释把所有“有利”写成“扶助方向”，把所有“相对不利”写成“制泄方向”。这会混淆身强与身弱：身强时，引擎列出的有利五行并不等同于扶助日主。

现已修正文案，统一使用：
- “对应简化扶抑参考列出的有利五行方向”；
- “对应简化扶抑参考列出的相对不利五行方向”。

标签计算仍只读取引擎 `fuYang.favorable` / `fuYang.unfavorable` 的五行集合，并同时比较大运天干五行和地支五行；没有引入月令司令、格局、调候、通关或刑冲合会综合判断。
