## 1. 审计目的与产品定位

本站不应停留在基础四柱计算器，也不应只把引擎接口名称堆成菜单。本项目的目标是建设一个完整的传统四柱资料产品：

1. **引擎能力充分利用**：优先调用仓库内引擎已经实现并公开的函数，不复制算法、不另造计算口径。
2. **数据完整且互相联动**：本命四柱作为中心，关联日柱、地支、十神、十二长生、神煞、干支关系、大运、流年、太岁等资料。
3. **形成产品特色**：以完整资料、关系图谱、时间轴、分层解释和易读的可视化作为差异点，而不是照搬其他排盘网站。
4. **计算与解释分层**：引擎计算结果、传统规则标签、前端归纳说明分别标明来源；不把单一神煞、十神或五行数量直接包装成吉凶断语。
5. **保持现有边界**：静态前端、本地引擎、本地计算；不连接 VPS2，不依赖第三方排盘 API。本轮仅审计，不修改引擎与业务代码。

## 2. 当前实现概况

当前前端保存四组核心状态：`lastBirth`、`lastChart`、`lastLuck`、`lastFavorable`。

- `lastChart`：`computeBazi(birth)` 的本命排盘结果，是四柱、五行统计、日主等本命展示的主数据源。
- `lastFavorable`：`computeFavorableElement(birth)` 的扶抑/调候结果。
- `lastLuck`：`computeLuckPillars({...birth, gender, count: 10})` 的大运结果。
- 三个接口内部存在重复计算本命的情况。后续可统一出生参数与结果管理，但保留现有变量和渲染入口，避免大规模重写。

当前页面已接入：四柱卡片、藏干十神、纳音、五行统计与扶抑参考、十二长生、四柱两两干支关系、大运时间轴、未来六年流年基础资料、神煞扫描。以上“已接入”不等于已完成真实浏览器验收或历法准确性独立验证。

## 3. 已核实的引擎公开能力分组

以下名称已在引擎末尾公开导出对象中核实。参数与返回字段只记录本次源代码检查能够确认的内容；未逐项完整展开的接口，标记为需要进一步字段级核对。

### A. 核心排盘与旺衰

| 接口 | 已核实用途/输入 | 返回与产品用途 |
|---|---|---|
| `computeBazi(opts)` | 输入公历年月日、时分、经度、时区偏移、未知时辰标记、换日口径等 | 返回本命四柱及 meta、五行统计等；是所有本命模块的根数据 |
| `computeFavorableElement(opts)` | 接收与排盘一致的出生参数，内部调用 `computeBazi` | 包含五行逐项计分、计分明细、扶抑评分/判定、调候等结构；当前前端读取 `fuYang.favorable`、`score.verdict`、`tiaoHou.ruleCn` 等路径 |
| `computeLuckPillars(opts)` | 出生参数，并使用 `gender`、`count`、`method`、`frame` 等选项；默认 `method=traditional`、`frame=civil` | 返回顺逆方向、起运信息、前运信息和大运序列；当前页面读取 `direction`、`start.chosen`、`preLuck`、`pillars[]` 等 |
| `tenGodOf(dayGan, gan)` / `deriveTenGod(dayGan, gan)` | 日干与待分析天干 | 十神名称及其关系分类；当前用于天干、藏干和流年十神展示 |
| `stemRelation(a,b)` | 两个天干 | 天干关系命中数组；当前用于本命四柱两两关系及流年对照 |
| `branchRelations(a,b)` | 两个地支 | 地支关系命中数组；当前用于本命四柱两两关系及流年对照 |

**参数口径注意**：当前前端调用大运接口时未显式传入 `method` 与 `frame`，因此按引擎默认值计算。后续应在产品说明或高级设置中明确展示所用口径；不要在未设计迁移方案前擅自改变默认值。

## 5. 推荐产品信息架构

首屏保留“出生信息 + 本命四柱 + 核心五行结构”作为主入口，避免初次访问信息过载。完整资料通过清晰的一级模块进入：

1. **命盘总览**：四柱、日主、五行分布、扶抑/调候摘要、关键提醒。
2. **四柱详解**：四柱剖面、日柱剖面、藏干、十神、纳音、十二长生、空亡、神煞。
3. **五行与十神**：五行计分口径、引擎计分明细、十神分布、十神柱位矩阵、五行生克关系。
4. **干支关系**：天干关系、地支关系、三合三会等组合；可切换本命、大运、流年参与对象。
5. **大运与流年**：起运依据、十年大运时间轴、逐年流年、流年月份、立春边界、太岁关系；本命/大运/流年联动。
6. **神煞与空亡**：按神煞类别、命中柱位和起法依据查看。
7. **传统资料库**：日柱百科、地支百科、十二长生、六十四卦等可检索知识页面。
8. **扩展工具**：八宅、每日择日、嫁娶择日、姓名五行等，待接口审计后独立规划。

## 6. 产品差异化原则

- **不是功能堆砌**：每个模块都回答“这是什么、从命盘哪里来、与哪些部分有关”。
- **可追溯**：重要结果显示来源柱位、参与干支、引擎接口或规则依据。
- **可联动**：点击某个天干、地支、十神或神煞，可以定位它在本命、大运、流年中的其他出现位置。
- **多口径透明**：起运方法、时区、真太阳时、换日口径、五行权重必须可见；默认设置保持兼容。
- **结论有边界**：引擎提供的是规则计算资料；传统流派差异、命理解释和人生建议要明确区分，不将单个神煞或一个十神直接等同吉凶。
- **移动端优先**：复杂数据用分组卡片、时间轴和折叠详情呈现；桌面端可提供更完整的矩阵/关系视图。

## 7. 分阶段实施顺序

### 阶段 1：审计与统一数据层（当前阶段）
- 完成 API 参数/返回字段矩阵，确认所有公开接口的真实输入输出。
- 设计统一命盘上下文对象，复用现有 `lastChart`、`lastLuck`、`lastFavorable`，不重写引擎。
- 为每个模块定义数据来源和缺失值策略。
- 不改 vendor，不改计算口径。

### 阶段 2：本命剖面中心
- 接入 `dayPillarProfile`、`branchProfile`、`tenGodPillarProfile`、`stageProfile`。
- 做日柱、地支、十神柱位、十二长生独立详情页。
- 四柱卡片与详情页双向联动。

### 阶段 3：关系图谱与本命增强
- 统一展示天干、地支、三合三会、刑冲合害破等关系。
- 接入空亡详细资料。
- 完善五行 breakdown、扶抑与调候数据展示。

### 阶段 4：大运/流年/太岁联动
- 建立本命、大运、流年三层关系计算与时间轴。
- 加入流年月份干支、立春精确边界、太岁关系。
- 大运倾向必须多依据综合展示，不做单一十神吉凶评级。

### 阶段 5：神煞体系与六十四卦资料库
- 神煞分组、落点、规则依据与空亡联动。
- 六十四卦独立入口，先实现卦象/纳甲资料展示。
- 在起卦规则尚未明确前，不自动从八字生成卦象。

### 阶段 6：扩展工具中心与体验完善
- 逐项审计八宅、每日、择日、姓名五行接口后再决定接入。
- 完善搜索、筛选、分享/打印、移动端导航、隐私说明和性能。

## 8. 关键风险与必须验收的边界

- 未知时辰：不得生成时柱内容；所有剖面、神煞、大运起运范围必须正确处理缺失时柱。
- 立春与节气：流年换年与月柱边界按引擎返回的节气时刻判断，不能按公历年份简单切换。
- 真太阳时与时区：出生时区、经度、中央经线、真太阳时 frame 必须一致；海外历史夏令时目前不会自动识别。
- 大运起运：traditional/precise 方法与 civil/true-solar frame 可能产生差异；必须在界面中标明。
- 神煞流派：显示引擎实际规则与起法依据，不宣称所有流派唯一正确。
- 六十四卦：必须明确卦序、起卦输入、动爻和起卦方法；八字与六爻不能混为同一计算。
- 独立基准：关键命例需与可信历书/独立排盘工具逐项核对；代码结构正确不等于历法结果已经验证。
- 真实环境：GitHub 提交、VPS1 拉取、浏览器验收是三个不同环节，不能相互替代。
